# Отчёт по итоговому проекту

## Тема

Двухсервисная система LLM-консультаций.

## Цель

Разработать распределённую систему, где аутентификация и прикладная LLM-логика разделены на независимые сервисы.

## Компоненты

### Auth Service

Auth Service реализован на FastAPI и отвечает за:

- регистрацию пользователя;
- хранение пользователя в SQLite;
- хранение пароля только в виде bcrypt hash;
- логин пользователя;
- выпуск JWT;
- проверку профиля через `/auth/me`.

JWT содержит поля:

- `sub` — id пользователя;
- `role` — роль пользователя;
- `iat` — время выпуска;
- `exp` — срок действия.

### Bot Service

Bot Service реализован на aiogram и отвечает за:

- получение JWT через команду `/token <jwt>`;
- проверку подписи и срока действия JWT;
- хранение JWT в Redis по ключу `token:<telegram_user_id>`;
- приём пользовательских сообщений;
- публикацию LLM-задачи в RabbitMQ через Celery.

Bot Service не регистрирует пользователей и не обращается к базе данных Auth Service.

### Celery Worker

Celery worker получает задачу `llm_request`, вызывает OpenRouter API и отправляет ответ пользователю в Telegram.

### RabbitMQ

RabbitMQ используется как брокер задач. Это позволяет не выполнять долгие LLM-запросы напрямую в handler-е Telegram-бота.

### Redis

Redis используется в двух ролях:

1. Хранилище JWT Telegram-пользователей.
2. Result backend для Celery.

## Пользовательский сценарий

1. Пользователь регистрируется в Auth Service.
2. Пользователь логинится и получает JWT.
3. Пользователь отправляет JWT боту через `/token <jwt>`.
4. Бот сохраняет JWT в Redis.
5. Пользователь отправляет вопрос.
6. Бот проверяет JWT.
7. Бот публикует задачу в RabbitMQ.
8. Celery worker вызывает OpenRouter.
9. Worker отправляет ответ в Telegram.

## Тестирование

В проекте реализованы тесты:

- тесты хеширования паролей;
- тесты генерации и декодирования JWT;
- интеграционный flow регистрации, логина и `/auth/me`;
- негативные тесты Auth Service;
- тесты JWT-проверки Bot Service;
- тесты Telegram handlers с fakeredis;
- тест OpenRouter-клиента через respx.

## Вывод

Проект соответствует архитектуре разделения ответственности: Auth Service выпускает JWT, Bot Service только проверяет JWT, а LLM-запросы выполняются асинхронно через RabbitMQ и Celery. Redis и RabbitMQ используются реально, а не формально.
